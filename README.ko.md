# Prompt Ladder

### 대충 쓴 초안을, 보내기 전에 Claude가 바로 움직일 수 있는 프롬프트로.

하고 싶은 일을 적고 `ctrl+x ctrl+p`를 누르면, 빠르게부터 깊게까지 비용이 다른 프롬프트를 고를 수 있습니다. 후보마다 토큰과 시간이 얼마나 드는지 함께 보여 줍니다.

```text
prompt-ladder 중간 규모 · 보통 난이도 — 대상 화면, 범위, 원하는 스타일이 모두 비어 있습니다. 먼저 저장소에 어떤 UI가 있는지 확인해야 하고…
1: 빠르게   ▰▱▱ UI 파일 하나만 찾아 기존 스타일 안에서 다듬기
2: 균형     ▰▰▱ UI 현황 파악·방향 확인 후 다듬고 실제 화면으로 검증 추천 ◂ 입력창
3: 깊게     ▰▰▰ 현황 탐색·방향 합의·구현·독립 디자인 리뷰까지 반복
0: 원문  r: 다시  x: 닫기  ctrl+x ctrl+p 다음 후보 · ctrl+x tab 후 숫자
가정: prompt-ladder에 브라우저로 볼 수 있는 웹 UI가 있다고 가정함. 없으면 대상을 사용자에게 확인하도록 함 / 새 스타일 방향이 아니라…
직접 호출 · 신규 18.1k · 캐시 1.1k · 출력 2.1k · 25초
───────────────────────────────────────────────────────────────────────────────────────────────
❯ prompt-ladder 프로젝트의 디자인을 예쁘게 만들어줘.
  시작 전에 아래를 확인하고, 내가 정하지 않은 부분은 짧게 물어봐:
  - 어떤 화면/컴포넌트가 대상인지 (전체인지 특정 화면인지)
  - 지금 톤을 유지할지, 새 방향을 원하는지
  진행 순서:
  1. 저장소에서 UI 코드와 이미 쓰고 있는 스타일 패턴(디자인 토큰, CSS 변수, 프레임워크)을 읽어.
  2. `make-interfaces-feel-better` 기준으로 문제점(간격, 위계, 정렬, 대비, 상태 표현)을 목록으로 만들고, 바꿀 계획을 짧게 보여줘.
  3. 기존 스타일과 구조를 지키면서 그 문제들만 고쳐. 기능, 텍스트, 관련 없는 코드는 건드리지 마.
  4. 앱을 실제로 띄워서 전후 화면을 확인하고, 빌드나 테스트가 통과하는지 확인해.
  완료 기준: 문제 목록의 각 항목이 해결됐고, 기존 동작이 깨지지 않았음.
```

<sub>실제 화면을 캡처한 것입니다. 초안은 `디자인 예쁘게 만들어줘` 한 줄이었고, 후보에 나오는 스킬 이름은 실행한 세션에 설치된 것입니다.</sub>

## 설치

Claude Code 세션의 프롬프트에서 실행합니다.

```text
/plugin install prompt-ladder --marketplace JunSeo99/prompt-ladder
/prompt-ladder setup
```

두 번째 줄은 `~/.claude/keybindings.json`의 Chat 컨텍스트에 `ctrl+x ctrl+p` → `command:prompt-ladder`를 추가합니다. 기존 바인딩은 절대 덮어쓰지 않습니다. 그 조합을 이미 다른 기능이 쓰고 있으면 알려 주기만 하고 아무것도 바꾸지 않습니다. 단축키가 바로 반응하지 않으면 Claude Code를 다시 시작하세요.

셸에서 설치하려면 `claude plugin install prompt-ladder --marketplace JunSeo99/prompt-ladder`를 실행합니다.

## 무엇을 해 주나

| | |
|---|---|
| **고쳐 쓰기가 아니라 사다리** | 비용 순으로 2~3개의 프롬프트를 냅니다: 빠르게, 균형, 깊게. `▰▱▱`–`▰▰▰` 미터는 각 후보가 에이전트에게 쓰게 하는 토큰과 시간을 나타냅니다. |
| **내 세션을 아는 프롬프트** | 다듬는 모델은 Claude가 보는 것을 그대로 봅니다. CLAUDE.md, 메모리, 실제로 설치된 스킬·서브에이전트·MCP 서버, 지금까지의 대화입니다. 이름은 백틱으로 짚고, 세션에서 확인되지 않는 이름은 띠에 따로 표시합니다. |
| **이미 낸 캐시를 다시 씀** | 첫 턴 이후에는 같은 모델로 세션을 fork하므로 입력 대부분을 프롬프트 캐시가 서빙합니다(측정값: 신규 1.4k, 캐시 59.6k). |
| **초안을 잃지 않음** | 다듬는 동안 초안을 건드리지 않았을 때만 추천 후보를 입력창에 넣습니다. `0`이면 원문으로 돌아가고, 프롬프트를 보내면 띠가 사라집니다. |
| **무거운 세션엔 핸드오프** | 컨텍스트가 400k 토큰을 넘으면(설정 가능) 균형·깊게 후보는 계속 쌓는 대신 핸드오프를 먼저 남기고 새로 이어갑니다. |

## 쓰는 법

1. 입력창에 초안을 씁니다. 대충 써도 됩니다.
2. `ctrl+x ctrl+p`를 누릅니다. 다듬는 동안 프롬프트 위 띠에 경과 시간이 표시됩니다.
3. 추천 후보가 입력창에 들어옵니다. 읽어 보고, 고치거나 그대로 Enter를 누르면 됩니다.

| 키 | 동작 |
|---|---|
| `ctrl+x ctrl+p` | 초안을 다듬습니다. 입력창에 원문이나 후보가 들어 있을 때 다시 누르면 다음 후보로 넘어갑니다: 원문 → 1 → 2 → 3 → 원문. 입력창을 고친 뒤 누르면 고친 내용으로 다시 다듬습니다. |
| `ctrl+x tab` 후 `1` `2` `3` | 그 후보를 입력창에 넣습니다(포커스는 입력창으로 돌아갑니다) |
| `0` | 원래 초안으로 되돌립니다 |
| `r` / `x` | 다시 다듬기 / 띠 닫기(`x`는 진행 중인 다듬기도 취소합니다) |
| `/prompt-ladder <내용>` | 커맨드 뒤에 쓴 내용을 다듬습니다. 단축키가 없을 때 씁니다. |

## 사다리

각 단계는 지금 작업의 크기에 맞춰집니다. 오타 수정이라면 깊게 단계도 작게 유지되고, 빠르게 단계도 결과는 정확해야 합니다.

| 단계 | 쓰는 것 | 얻는 것 |
|---|---|---|
| **1 빠르게** `▰▱▱` | 토큰이 가장 적고 가장 빠릅니다. 초안과 맥락이 이미 정해 둔 범위에서 바로 실행하고, 관련 파일만 읽습니다. 서브에이전트·조사·새 스킬 없이 가벼운 확인 한 번으로 끝냅니다. | 작고 분명한 일의 답 |
| **2 균형** `▰▰▱` | 관련 코드와 기존 패턴을 먼저 읽고, 짧게 계획하고, 구현한 뒤 테스트나 실행으로 검증합니다. 확실히 맞는 스킬은 하나까지 씁니다. | 코드베이스에 맞고 검증된 결과 |
| **3 깊게** `▰▰▰` | 토큰과 시간이 가장 많이 듭니다. 레퍼런스나 최신 자료를 모으고, 탐색은 서브에이전트에 병렬로 맡기고, 맞는 스킬을 불러와 계획·구현합니다. 그다음 독립 리뷰를 받아 기준을 넘을 때까지 반복합니다. | 크거나 모호하거나 품질이 중요한 일의 최선 |

다듬는 모델은 먼저 초안의 규모와 난이도를 판단하고(띠 맨 위에 표시) 한 단계를 추천합니다. **후보를 2개**로 설정하면 작업을 감싸는 짝을 고릅니다. 작고 분명한 일은 빠르게+균형, 크거나 모호한 일은 균형+깊게입니다.

모든 후보가 지키는 규칙은 이렇습니다.

- 의도, 제약, 이름, 경로, 숫자는 그대로 둡니다.
- 요청하지 않은 목표는 더하지 않습니다.
- 꼭 가정해야 하는 것은 프롬프트 안에 적어서 에이전트가 확인하게 하고, 띠에도 따로 보여 줍니다.
- 사용자가 평소에 정해 둔 지시는 어기지 않습니다.

## 동작 방식

```text
ctrl+x ctrl+p ─► /prompt-ladder ─► 초안 읽기 ─┬─ 끝난 턴이 있음 ─► $.model.fork (같은 모델, 캐시된 프리픽스)
                                             └─ 첫 프롬프트 / /clear 직후 ─► 세션 모델로 $.model.complete
                                                                             (CLAUDE.md·메모리·스킬·도구·에이전트를 모아서)
                    ◄─ JSON 사다리 ◄─ 파싱, 세션 기준으로 이름 확인 ◄─┘
프롬프트 위 띠 + 추천 후보를 입력창에 (초안이 그대로일 때만)
```

- **fork가 먼저입니다.** fork는 세션의 마지막 요청(시스템 프롬프트, 도구, 메시지)을 그대로 다시 보내고, 끝에 다듬기 요청만 붙입니다. 프리픽스 캐시는 같은 모델에서만 맞으므로, 더 싼 모델 대신 일부러 세션 모델을 씁니다. 캐시되지 않는 입력은 끝에 붙는 지시문(약 1k 토큰)뿐입니다.
- **첫 턴 전에는 직접 호출합니다.** 아직 fork할 대화가 없으니 맥락을 직접 모읍니다. CLAUDE.md 파일과 메모리 인덱스, 스킬·커맨드, 서브에이전트 종류, 내장 도구와 MCP 서버, git 브랜치, 최근 메시지입니다. 부분마다 상한이 있고 맥락 블록은 캐시되므로, 몇 분 안에 다시 다듬으면 대부분을 캐시에서 읽습니다.
- **띠**는 `AbovePrompt` 자리에 `ui.render` 훅으로 그리며, 숫자 단축키와 경과 시간 표시가 있습니다.

Claude Code 2.1.317, Opus 5.5, 스킬·커맨드가 약 400개인 환경에서 측정했습니다.

| 경로 | 신규 입력 | 캐시 | 출력 | 시간 |
|---|---|---|---|---|
| 직접 호출(세션 첫 프롬프트) | 18–19k | 0–1k | 1.5–2.1k | 15–25초 |
| 세션 fork(한 턴 이후, 컨텍스트 약 60k) | 1.4k | 59.6k | 2k | 18초 |

fork는 전체 컨텍스트를 캐시로 읽으므로 세션이 커질수록 비용도 커집니다. 아래 핸드오프가 있는 이유 중 하나입니다.

### 무거운 세션

단축키를 누르면 세션의 컨텍스트 크기를 읽습니다(`$.session.usage()`, 비용 없음). `handoffAt`(기본 400k 토큰) 이상이면 띠에 표시하고, 다듬는 모델에게 이렇게 계획하라고 알립니다.

- 빠르게는 작은 일이면 이 세션에 남아도 됩니다.
- 균형과 깊게는 핸드오프부터 남깁니다. 핸드오프 스킬이 있으면 그걸 쓰고, 없으면 목표·결정·현재 상태·다음 단계·핵심 파일을 짧게 적습니다.
- 그다음 새 세션에서 이어갈 지점을 알려 주고 멈추거나, 깨끗한 컨텍스트의 서브에이전트에 작업 전체를 맡기고 결과만 받습니다.

## 설정

`/config`의 prompt-ladder 항목에서 바꿀 수 있고, `/plugin`으로 설치할 때도 보입니다.

| 옵션 | 기본값 | |
|---|---|---|
| `candidates` | `3` | `3`: 빠르게·균형·깊게. `2`: 작업을 감싸는 짝. |
| `autofill` | 켬 | 다듬기가 끝나면 추천 후보를 입력창에 넣습니다. 끄면 고를 때까지 초안이 그대로 있습니다. |
| `handoffAt` | `400` | 균형·깊게가 핸드오프를 계획하기 시작하는 컨텍스트 크기(천 토큰 단위). `0`이면 끕니다. |

띠의 언어는 Claude Code의 `language` 설정을 따릅니다. 설정이 없으면 초안이 한국어일 때 한국어로 보여 줍니다. 후보는 항상 초안과 같은 언어로 씁니다.

## 개인정보와 비용

- **보내는 것.** 초안은 세션과 같은 모델·계정으로만 갑니다. 직접 호출일 때는 위에 적은 맥락이 함께 갑니다. 그 밖의 곳으로는 아무것도 보내지 않습니다.
- **쓰는 파일.** 디스크에는 `/prompt-ladder setup`을 실행했을 때 `~/.claude/keybindings.json` 하나만 씁니다. 자세한 내용은 [SECURITY.md](SECURITY.md)에 있습니다.
- **비용.** 한 번 누를 때마다 요청이 하나 나가고, 세션의 다른 요청과 똑같이 청구됩니다. 띠에 신규·캐시·출력 토큰이 표시됩니다.
- **취소.** 직접 호출은 `x`로 취소됩니다. fork는 보낸 뒤에는 멈출 수 없어서, `x`를 누르면 결과가 도착했을 때 버립니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 단축키가 반응하지 않음 | 바인딩이 없습니다. `/prompt-ladder setup` 후 Claude Code를 다시 시작하고, `/keybindings`에서 `command:prompt-ladder`를 확인하세요. |
| setup이 조합이 이미 쓰인다고 함 | `ctrl+x ctrl+p`를 다른 기능이 쓰고 있습니다. `/keybindings`에서 비어 있는 다른 조합을 `command:prompt-ladder`에 연결하세요. |
| 띠가 안 보임 | 띠는 터미널과 데스크톱 앱에서만 그려지고, VS Code 확장에서는 안 보입니다. 그 대신 입력창에 넣을 수 없을 때는 후보를 대화 기록 줄로 보여 줍니다. 접혀 있을 때(`ctrl+x ctrl+a`로 토글)나 설문이 띠를 쓰고 있을 때도 숨겨집니다. |
| "초안에 붙여넣은 블록이나 이미지가 있어…" | 입력창은 붙여넣기와 이미지를 자리표시자로 보여 주는데, 다듬으면 그 내용이 빠집니다. 글을 먼저 다듬고 그다음 붙여 넣으세요. |
| 빈 입력창에 숫자를 쳤더니 후보가 골라짐 | 빈 입력창에 숫자만 치면 Claude Code가 띠의 그 번호 버튼을 누릅니다. 사다리를 보내거나 닫고(`x`) 치거나, 다른 글자로 시작하세요. |
| "세션에서 확인 못 한 이름: …" | 프롬프트가 세션에 없는 스킬·에이전트·도구를 짚었습니다. 빼거나 설치한 뒤 보내세요. |
| "그사이 초안을 고치셔서…" | 다듬는 동안 입력해서 입력창을 그대로 두었습니다. `ctrl+x tab` 후 숫자로 고르거나, 새 내용에서 단축키를 다시 누르세요. |

## 요구 사항

- Claude Code 2.1.299 이상(띠의 리치 버튼과 텍스트 굵기). 2.1.317에서 테스트했습니다.
- mod는 얼리 액세스 API라서 이벤트와 메서드가 릴리스마다 바뀔 수 있습니다. 업데이트 후 문제가 생기면 `claude --version`과 함께 이슈를 남겨 주세요.

## 개발

```bash
git clone https://github.com/JunSeo99/prompt-ladder && cd prompt-ladder
claude --plugin-dir .            # mod를 불러온 세션 실행 (에디터용 .claude-plugin/types 생성)
claude plugin test .             # 파서·규칙·키바인딩 병합·모델을 스텁한 전체 흐름
claude plugin validate .         # 엔진이 매니페스트와 훅 모듈에서 읽는 내용
npx -p typescript tsc -p .       # 설치된 빌드의 선언으로 strict 타입 검사
```

구조와 기여 방법은 [README.md](README.md#development)와 [CONTRIBUTING.md](CONTRIBUTING.md)를 보세요.
